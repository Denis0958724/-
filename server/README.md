# Сервер «Мікро-консультацій»

Сервер тримає всі дані, перевіряє вхід, бронювання і документи, відправляє листи і запускає власну модель пошуку фахівців. Сторінка `prototype.html` лежить поруч з текою `server` і відкривається через сервер.

## Що потрібно

- **Node.js 22.13 або новіший** (підійде LTS 22 або 24). Перевірити: `node -v`. Завантажити: https://nodejs.org
- Інтернет потрібен лише для першого `npm install` і для відправки листів через Gmail. Модель пошуку і перевірка документів працюють без інтернету.

## Запуск

```
cd server
npm install
npm start
```

Потім відкрийте **http://localhost:3000**.

Поки пошта не налаштована, сервер працює, але листи з кодом не відправляються, і сторінка прямо про це скаже. Налаштування нижче.

## Пошта (Gmail з паролем застосунку)

1. Увімкніть двоетапну перевірку в Google-акаунті, з якого підуть листи.
2. Відкрийте https://myaccount.google.com/apppasswords і створіть пароль застосунку, наприклад з назвою «Askly». Google покаже 16 символів.
3. Скопіюйте файл `.env.example` у `.env` (у тій самій теці `server`) і впишіть:
   ```
   GMAIL_USER=ваша.адреса@gmail.com
   GMAIL_APP_PASSWORD=ці16символів
   ```
4. Перезапустіть сервер. У консолі має бути `Пошта: gmail`. Якщо написано `gmail_error`, пароль або адреса неправильні.

Пароль застосунку не пишіть у чат і не комітьте: файл `.env` у `.gitignore`.

Для розробки без пошти є режим `MAIL_MODE=log` у `.env`: листи не відправляються, а друкуються в консоль сервера з позначкою «РЕЖИМ РОЗРОБКИ». На справжньому сервері його не вмикайте.

## Що де лежить

| Тека чи файл | Що там |
|---|---|
| `server.js` | Запуск, налаштування з `.env`, сторінка, розсилка щохвилини, прибирання щогодини |
| `lib/api.js` | Усі запити сторінки. Кожен перевіряє сесію і чиї це дані |
| `lib/auth.js` | Коди з листа, сесії, паролі (scrypt), обмеження частоти |
| `lib/docs.js` | Перевірка документів: тип за вмістом, якість фото, розпізнавання тексту (OCR) |
| `lib/notify.js` | Листи про нових фахівців і стани консультацій |
| `lib/rules.js` | Часові пояси, слоти, перевірки полів |
| `lib/demo.js` | Демо-фахівці. Вимкнути: `SEED_DEMO=0` у `.env` |
| `ai/` | Власна модель тем і пошук фахівців. Навчання в `ai/train` |
| `data/` | База SQLite, секрет сесій, файли дипломів. Створюється сама, у git не йде |

## Модель пошуку

Модель навчена на власному наборі прикладів (`ai/train/data_*.py`) і працює всередині сервера. Точність на тестовому наборі, якого вона не бачила під час навчання: 82%. Якщо модель не впевнена, сторінка перепитує людину.

Перенавчити після зміни прикладів (потрібні Python 3 і `pip install numpy scipy scikit-learn`):

```
cd server/ai/train
python3 train.py
```

## Безпека, коротко

- Вхід клієнта лише за кодом з листа: 6 цифр, 10 хвилин, 5 спроб, новий код не частіше разу на хвилину, код одноразовий і зберігається лише як хеш.
- Бронювати може тільки клієнт з підтвердженою поштою. Ціну, ім'я і клієнта бере сервер, а не запит.
- Чужі бронювання недоступні: на чужий id сервер відповідає так само, як на неіснуючий.
- Сесія в cookie HttpOnly. Вихід знищує її на сервері.
- Пароль фахівця зберігається лише як хеш. Після 5 невдалих спроб вхід блокується на 15 хвилин.
- Документ, що посвідчує особу, після перевірки не зберігається. Дипломи зберігаються для модератора 30 днів, файли незавершених реєстрацій видаляються через добу.
- Сервер за замовчуванням слухає лише цей комп'ютер (`HOST=127.0.0.1`). Щоб викласти в інтернет, потрібні HTTPS і `BASE_URL=https://...`.

## Чого ще немає

- Модератора і програми для адміна: заявки фахівців схвалюються автоматично з позначкою «без перевірки».
- Справжньої оплати і відеозв'язку: вони імітуються, як і раніше.
- Перевірка документів відсіює те, що точно не документ або не читається. Справжність документа і особу вона не доводить.
